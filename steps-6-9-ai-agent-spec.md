# Steps 6–9 Redesign: AI Industry Specialist Agent — Claude Code Spec

> **What this is:** Complete redesign of Steps 6-9. Step 6 becomes pure CVM data
> analysis (no external context). Step 7 introduces an AI Industry Specialist Agent
> that reasons about the findings. Step 8 synthesizes into executive summary.
> Step 9 is open Q&A with the AI agent.
>
> **CRITICAL:** Do NOT change Steps 1–5. They are complete and working.
> **CRITICAL:** Do NOT change the detection algorithms in `pattern_detector.py`.
> The algorithms, thresholds, and DQ classification rules are validated.

---

## Architecture Overview

```
Step 6: Pattern Detection & Risk Assessment
  └─ Input: enriched df from Step 5
  └─ Logic: detect_patterns() + enrich() [stripped of macro context]
  └─ Output: findings + risk score + finding categories
  └─ NO macro context, NO hypotheses, NO external knowledge

Step 7: AI Industry Specialist Agent
  └─ Input: all findings from Step 6
  └─ Logic: sends findings to Claude API via WebSocket
  └─ Output: streamed AI analysis (macro context + hypotheses + data readiness)
  └─ This is an LLM call, not deterministic

Step 8: Executive Summary
  └─ Input: Step 6 data findings + Step 7 AI analysis
  └─ Output: structured narrative with story arc

Step 9: Open Q&A with AI Agent
  └─ Input: user questions (suggested menu + free text)
  └─ Context: Steps 6 + 7 results in conversation history
  └─ Output: streamed AI responses in chat interface
```

## Step 6: Pattern Detection & Risk Assessment (Simplified)

### What to REMOVE from Step 6:

1. **Remove macro context annotations from findings.** Currently `_add_macro_context_to_findings()` 
   appends macro context strings to finding insights. Remove this call from `detect_patterns()`.
   Findings should NOT have `macro_context` fields.

2. **Remove the `MACRO_CONTEXT` dict from `pattern_detector.py`.** This data (COVID, supercycle, 
   Ukraine war, etc.) should NOT be in the pattern detection layer. It will be generated by the 
   AI agent in Step 7 instead.

3. **Remove macro timeline from the Step 6 API response.** The `macro_timeline` array currently 
   comes from `enrichment.enrich()`. Remove it from the Step 6 response. Step 6 should return 
   only data-derived results.

4. **Remove the MacroTimeline component from Step 6 frontend.** The SVG timeline we built 
   today should be removed from `Step6CoreAnalysis.jsx`. (It may be reused in Step 7 or 8 later,
   but not in Step 6.)

5. **Remove macro context from the FindingChart supercycle annotation.** The "Commodity 
   supercycle" label annotation on the COGS drift chart in Step 6 should be removed — Step 6
   doesn't know about macro events. Keep the other chart annotations (labeled averages, 
   breakeven lines, compression rates, divergence indicators) since those are derived from 
   the data itself.

### What to KEEP in Step 6:

- All 6 detection algorithms (unchanged)
- DQ classification (anomaly_type, confidence_score)
- Composite signals (STRUCTURAL_COMPETITIVENESS_ISSUE, NEGATIVE_OPERATING_LEVERAGE, etc.)
- Risk scoring (magnitude, persistence, confirmation, peer_gap, data_confidence)
- Finding categorization (core / supporting / contextual / anomalies)
- RiskGauge component
- Finding cards with Show Chart toggle
- All chart annotations that are DATA-DERIVED (not context-derived)

## Step 7: AI Industry Specialist Agent (NEW — replaces old hypothesis generator)

### Backend

**Delete:** `backend/pipeline/hypothesis_generator.py` (the hardcoded domain knowledge map)

**Delete:** `backend/steps/step7_hypotheses.py` (the old deterministic endpoint)

**New file:** `backend/steps/step7_ai_agent.py`

This step uses WebSocket streaming (same pattern as current Step 9) to call the Claude API.

**WebSocket endpoint:** Reuse `/ws/llm` but add a `step` field to the message to distinguish 
Step 7 from Step 9 calls. Or create a separate endpoint `/ws/agent` — your choice on routing.

**System prompt for Step 7:**

```
You are a senior industry specialist and financial analyst with deep expertise in
Brazilian capital markets, commodity-driven industries, and corporate financial 
analysis. You have access to CVM (Securities Commission of Brazil) public filings.

You have been given the results of an automated financial pattern detection analysis
on a Brazilian company. The analysis used only public CVM data (DFP annual and ITR 
quarterly filings) and detected patterns using statistical methods — no external 
context was applied.

Your task is to provide expert context and interpretation:

1. MACRO CONTEXT: What economic, industry, and market events during the analysis 
   period (2020-2025) might explain the patterns detected? Be specific about timing 
   and mechanisms — don't just list events, explain how they connect to the specific 
   findings.

2. HYPOTHESES: For each structural finding (cost deterioration, margin compression), 
   generate 5-7 possible root causes. For each hypothesis:
   - State the theory clearly
   - Explain the specific mechanism (how would this cause show up in the numbers?)
   - Identify what internal data source would confirm or refute it
   - Rate your confidence (HIGH/MEDIUM/LOW)

3. DATA READINESS ASSESSMENT: What questions does this analysis raise that public 
   data cannot answer? For each question, identify the specific internal data source 
   needed and why it matters.

Be specific to the company and sector. Reference actual industry dynamics, not 
generic financial theory. Write in {language}.
```

```

## Findings (ordered by narrative importance)

### Core Findings
{for each finding in core category:}
- {finding_id}: {pattern} — {description}
  Data: {key data points}

### Supporting Evidence
{for each finding in supporting category:}
- {finding_id}: {pattern} — {description}
  Data: {key data points}

### Contextual Patterns
{for each finding in contextual category:}
- {finding_id}: {pattern} — {description}
  Data: {key data points}

### Anomalies
{for each finding in anomalies category:}
- {finding_id}: {pattern} — {description}
  Data: {key data points}

Provide your expert analysis.
```

**Model:** `claude-sonnet-4-20250514`

that demonstrates what the output would look like. Cache the first successful live 
response for fallback on subsequent failures.

**Pipeline state:** Store the full AI response text in `pipeline_state["step7"]` 
so Step 8 and Step 9 can reference it.

## Step 9: Open Q&A with AI Agent (Redesigned)

### Backend

**File:** `backend/steps/step9_llm_analysis.py` (major update)

Step 9 is now a **conversational interface**, not a single-finding analysis.

**WebSocket protocol update:**

The WebSocket at `/ws/llm` (or `/ws/agent`) now accepts messages with:

```json
{
  "step": 9,
  "message": "What about the FX impact on Braskem's costs?",
  "conversation_history": [
    { "role": "user", "content": "previous question" },
    { "role": "assistant", "content": "previous answer" }
  ]
}
```

**System prompt for Step 9:**

```
You are a senior industry specialist and financial analyst. You previously analyzed 
a Brazilian company's CVM financial data and provided an initial assessment.

You are now in a follow-up conversation. The user may ask about:
- Specific findings or patterns from the analysis
- Industry dynamics or macro context
- What internal data would be needed to investigate further
- Comparisons with peers or industry benchmarks
- Specific hypotheses and how to test them

Be concise and specific. Reference the actual numbers from the analysis when relevant.
If asked about something outside the scope of the financial analysis, acknowledge the 
limitation and redirect to what the data shows.

Write in {language}.
```

**Context injection:** The conversation always starts with the Step 6 findings summary 
and Step 7 AI analysis as the first assistant message in the history. This gives Step 9 
full context without re-sending the entire prompt.

```python
base_context = [
    {
        "role": "user", 
        "content": f"Here is the financial analysis for {company}:\n\n{step6_summary}\n\nAnd here is the industry specialist assessment:\n\n{step7_response}"
    },
    {
        "role": "assistant",
        "content": "I have the full analysis context. What would you like to explore further?"
    }
]
# Then append user's conversation_history
messages = base_context + conversation_history + [{"role": "user", "content": new_message}]
```

**Model:** `claude-sonnet-4-20250514`
**Max tokens:** 1500 (shorter responses for Q&A)
**Temperature:** 0.7

### Frontend

**New file:** `frontend/src/steps/Step9QA.jsx` (replaces `Step9LLMAnalysis.jsx`)

**Layout:**

1. **Suggested questions menu** (top of the step):
   A horizontal row of clickable question chips/buttons. Clicking one sends that 
   question to the AI agent. Suggested questions:

   ```json
   [
     "What macro events explain the 2022 COGS inflection?",
     "What are the most likely root causes of the COGS deterioration?",
     "What internal data would be needed to confirm the top hypothesis?",
     "How does Braskem's cost structure compare to global peers?",
     "What would a recovery scenario look like?"
   ]
   ```

   Portuguese equivalents:
   ```json
   [
     "Quais eventos macro explicam a inflexão do CPV em 2022?",
     "Quais são as causas mais prováveis da deterioração do CPV?",
     "Quais dados internos seriam necessários para confirmar a principal hipótese?",
     "Como a estrutura de custos da Braskem se compara com pares globais?",
     "Como seria um cenário de recuperação?"
   ]
   ```

2. **Chat area** (main content):
   - Scrollable chat-style interface
   - User messages right-aligned (blue bubbles or similar)
   - AI responses left-aligned (gray/white bubbles)
   - AI responses stream in token by token (same WebSocket streaming pattern)
   - Markdown rendering in AI responses (headers, bullets, bold)

3. **Input area** (bottom):
   - Text input field with placeholder: "Ask anything about the analysis..." / 
     "Pergunte qualquer coisa sobre a análise..."
   - Send button (or Enter key)
   - Disabled while AI is streaming

4. **Conversation state:**
   - Maintain conversation history in React state (useReducer or useState)
   - Each exchange: { role: "user", content: "..." } + { role: "assistant", content: "..." }
   - Send full conversation history with each new message (so AI has context)
   - Clear conversation when navigating away and back (or offer a "New conversation" button)

**The "Run Step" button is NOT used for Step 9.** Instead, the interaction is driven 
by the suggested question chips and the text input. The step is "active" as soon as the 
user navigates to it.

**Note:** Step 9 does NOT auto-run. The user must either click a suggested question or 
type a question to start the conversation.
